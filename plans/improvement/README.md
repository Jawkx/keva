# Improvement Plans

Generated by an `/improve` audit on 2026-06-30, written against commit `9c454b4`.
These are self-contained implementation plans for an executor (human or agent)
with no prior context. Each executor: read the plan fully before starting, run
its verification commands, honor its STOP conditions, and update your row below
when done.

> These live under `plans/improvement/` to stay separate from the design docs in
> `plans/` (architecture, data-model, auth, etc.), which are not improvement plans.

## Recommended order

`01` first — it is a production auth outage (≈48% of minted API tokens cannot
authenticate against Postgres). The other three are independent of each other and
of `01`, so they can be done in any order or in parallel. Suggested sequence by
leverage: **01 → 02 → 03 → 05**.

## Dependency notes

- None of these four plans depend on one another. (Plan 02 touches the Postgres
  store and core tests; 03 and 05 touch the web app; 01 touches the server — no
  file overlap.)

## Scope of this directory

These four are the subset selected for planning (audit findings #1, #2, #3, #5).
Other findings from the same audit were intentionally **not** turned into plans
here:

- **#4 — code-split the heavy PDF/CSV viewers** (`FileDetail.tsx` statically
  imports `PDFViewer`/`CsvViewer`): real perf finding, not selected for a plan
  in this batch.
- **Docs drift**: `plans/api.md` / `plans/data-model.md` document
  `PATCH /items/:id/properties`, but the implemented route is `PATCH /api/items/:id`;
  `confirm` validates `size` only though docs say "size/etag". Docs-only fix.
- **S3 `CopyObject` trusts HTTP 200** (`packages/core/src/s3.ts`): a Phase-3
  hardening note (R2, the default backend, may not exhibit the 200-with-error
  behavior).

### Considered and rejected (so they aren't re-audited)

- **Token regex "consecutive underscores, minor"** — this was a *misdiagnosis*
  of finding #1 during the audit; the real fix is plan 01.
- **`lodash@4.18.1` workspace override** — 4.18.1 is the current published
  lodash; the override only dedups `glide-data-grid`'s copy. Not a bug.
- **FilesPage `invalidateQueries(["items"])` on upload under active search** —
  correct behavior (a new item's match against the active filter is unknown, so
  a refetch is right); only mildly over-broad.
- **SHA-256 token hashing, no-JWT, AND-only queries, tenant-scoped sequential
  scans, `null`-as-value, the dev loopback blob route, the in-memory store** —
  all explicit, documented design decisions (see `plans/*.md`).
- **Rate limiting / audit logging / cookie-flag hardening / per-member RBAC** —
  operator/edge concerns or explicitly deferred to "multi-tenant hardening"
  (`apps/server/src/better-auth.ts` comment + `plans/roadmap.md` Phase 5).
- **esbuild advisory `GHSA-67mh-4wv8-2f99` (moderate)** — dev/build-time only
  (`better-auth › drizzle-kit › esbuild`), not runtime-reachable, and below CI's
  `--audit-level high` gate.
